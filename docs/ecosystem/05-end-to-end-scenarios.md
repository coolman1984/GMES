# E5) سيناريوهات انتقال البيانات من البداية للنهاية

كل سيناريو عليه علامة: ✅ **مُنفَّذ ومُختبر آليًا** في الشريحة الأولى، أو 📐 **مُصمم** فقط.
أسماء الاختبارات في `apps/link-mizan/test/` و `apps/mes-server/test/`.

---

### س1 — الصنف والمخزن ينزلوا من المحاسبة للتصنيع ✅
```
ميزان: محاسب ينشئ صنف RM-STEEL وصنف FG-CHAIR والمخزن MAIN
   → link-mizan يقرأ /api/items و /api/inventory/warehouses (قراءة فقط)
   → يبني eco.item.v1 بهوية v5 حتمية + version = بصمة المحتوى
   → POST /eco/v1/inbox في التصنيع
التصنيع: يطبق اللقطة فقط لو المحتوى اتغير؛ المرآة للقراءة؛ مفيش شاشة تعدّلها
```
**الاختبار:** تشغيل مرتين = صفر تغييرات في المرة الثانية؛ تغيير الاسم في ميزان يظهر في التصنيع.

### س2 — أمر إنتاج → استهلاك خامات → صرف للإنتاج في المحاسبة ✅
```
التصنيع: CreateWorkOrder(FG-CHAIR ×10) → Release → ConsumeMaterial(RM-STEEL 25 كجم من MAIN، العامل، الوردية)
   ├─ دفتر الحركات: سطر CONSUME (+hash)       ┐ نفس المعاملة
   └─ outbox: mes.material.consumed.v1          ┘
link-mizan: يسحب الحدث → يتأكد إنه لم يُطبق (inbox محلي + بحث بالمرجع في ميزان)
   → POST /api/inventory/operations {kind:'adjustment', qty:-25000, unitCost:null (متوسط),
      counterAccountId: WIP, reference: 'eco:<event-id>', post:true}
ميزان: قيد تلقائي مدين WIP / دائن المخزون بمتوسط التكلفة — **ميزان هو اللي قرر القيمة**
link-mizan: يقرأ القيمة المرحّلة، يضيفها لرصيد WIP للأمر، يرسل Ack(applied, ADJ-00001)
```

### س3 — اكتمال المنتج → استلام بتكلفة فعلية ✅
```
التصنيع: ReportCompletion(FG-CHAIR 4 قطع) ثم (6 قطع، is_final=true)
link-mizan: قيمة التحميل = رصيد WIP المتبقي × الكمية ÷ الكمية المتبقية من المخطط؛
            الاكتمال الأخير ياخد **كل** الباقي (نفس قاعدة ميزان "آخر وحدة تاخد الباقي")
   → adjustment +qty بتكلفة الوحدة، الحساب المقابل WIP
ميزان: مدين المخزون / دائن WIP. بعد الاكتمال الأخير رصيد WIP للأمر ≈ صفر
```
**الاختبار:** ميزان صحي (`/api/system/health` كله ok، والتقييم = حسابات المخزون)، والقيود متوازنة،
ورصيد WIP المتبقي للأمر ≤ فرق التقريب المسموح (سعر الوحدة في ميزان رقم صحيح — ADR-019).

### س4 — المحاسبة متوقفة أثناء الإنتاج ✅
```
ميزان مطفي → التصنيع يكمل تسجيل (مش بيعرف أصلًا إن ميزان مطفي)
link-mizan: كل محاولة تفشل اتصالًا → المؤشر لا يتقدم → إعادة محاولة
ميزان يرجع → link-mizan يكمل من المؤشر → كل حدث يُطبق مرة واحدة بالترتيب
```

### س5 — الموصل وقع بعد الترحيل وقبل ما يسجل ✅
```
link-mizan رحّل ADJ في ميزان ثم انهار قبل حفظ حالته
إعادة التشغيل → نفس الحدث → بحث في ميزان بالمرجع eco:<event-id> → موجود → يُعلّم applied بدون ترحيل ثاني
```
**الاختبار:** حقن عطل صناعي بعد الترحيل؛ عدد مستندات ميزان بنفس المرجع = 1.

### س6 — رصيد غير كافٍ في المحاسبة ✅
```
التصنيع يستهلك 500 كجم والمخزن فيه 100 → ميزان يرد stock.insufficient
link-mizan: Park للحدث + Ack(parked, stock.insufficient) + **كل أحداث نفس الأمر بعده تنتظر**
   (أوامر الإنتاج الأخرى تكمل عادي)
التصنيع: شاشة/واجهة "استثناءات التكامل" تعرض الحدث المحجوز وسببه
المخزن يستلم خامات في ميزان → link-mizan يعيد المحاولة → يُطبق → الأحداث المنتظرة تُطبق بالترتيب
```

### س7 — مسح مكرر في المحطة ✅
نفس `command_id` مرتين → سطر واحد في الدفتر → حدث واحد في الـFeed → مستند واحد في ميزان.

### س8 — المحطة ومكانها الحقيقي في الثري دي 📐
```
الثري دي: المخطط يرسم خط الإنتاج، ويربط كل ماكينة بمحطة موجودة في التصنيع:
          item.meta["eco.ref"] = "eco:station:<uuid>"   (حقل pack حر موجود فعلًا، بلا تعديل في النواة)
          → "تصدير لقطة" eco.layout.snapshot.v1 (ملف JSON)
التصنيع: استيراد اللقطة (قراءة) → كل محطة تعرف (layout_id, item_id, position)
العرض الحي: متصفح الإدارة يفتح عارض الثري دي، ويشترك في SSE التصنيع
            /eco/v1/live (حالة المعدات والأوامر) ويلوّن العناصر المربوطة
```
**ليه مش API مباشر؟** سيرفر الثري دي مقفول على 127.0.0.1 عمدًا (بيشغّل وكلاء). فتحه على الشبكة = ثغرة.

### س9 — الموظف والوردية معروفين 📐 (جزئيًا ✅)
✅ كل حدث يحمل `performed_by {user, person?}` و`production_date` و`shift`.
📐 مصدر الشخص والوردية: تطبيق أفراد مستقبلي (`eco.person`, `eco.shift_pattern`)؛ الآن التصنيع مالك بديل.

### س10 — عميل اشترى التصنيع فقط، ثم أضاف المحاسبة 📐
```
قبل: التصنيع مالك بديل للأصناف والمخازن (هويات v7 محلية)
بعد تركيب ميزان: معالج تبنّي: يطابق بـSKU/الكود → يعرض (متطابق / موجود هنا فقط / موجود هناك فقط / مختلف)
   → شخص يقرر لكل فرق → الهويات المحلية تُربط بهويات ميزان (alias) → الملكية تنتقل → المرآة للقراءة
```
لا دمج تلقائي. التاريخ القديم يحتفظ بالهوية القديمة + alias للجديدة.

### س11 — الإدارة ترى المصنع كمنظومة واحدة 📐
لوحة واحدة (في التصنيع) تقرأ: الحالة الحية (التصنيع) + القيم المالية المرحّلة (Acks من ميزان تحمل
أرقام المستندات والقيم) + المخطط (لقطة الثري دي). **كل رقم عليه مصدره.**

### س12 — أمر إنتاج قادم من G-MES سامسونج (مستورد، قراءة فقط) 📐
مشروع الأتمتة يصدّر "Production Plan by Order(Line)" (`P1112UM00`) كملف Excel موثّق التاريخ والقسم →
مستورد في التصنيع ينشئ أوامر عمل بأصل `origin = samsung-gmes`. **لا كتابة في G-MES أبدًا** (قاعدة 2.5 هناك).
