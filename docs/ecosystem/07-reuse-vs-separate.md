# E7) ما يُعاد استخدامه وما يبقى منفصلًا

**المبدأ:** نعيد استخدام **الأنماط والعقود**، لا نشارك **قواعد البيانات ولا محركات الحالة**.
الكود المشترك الوحيد بين المستودعات الآن هو `eco-contracts` (عقود فقط). أي مكون واجهة مشترك يُستخرج
لاحقًا كحزمة بقرار (لا نسخ ولصق يتباعد بمرور الوقت).

## E7.1 من ميزان (المحاسبة)
| نأخذ | كيف |
|---|---|
| عقد الموديول (`AppModule`: id, dependsOn, migrations, permissions, roles, routes, health) | GMES يتبنى نفس الشكل (بدل تصميم `module.yaml` السابق) → مطوّر واحد يفهم الاثنين |
| اختبار الحدود (Boundaries test) + Editions | نفس الفكرة: موديول لا يستورد موديول آخر؛ بناء نسخة بموديولات مختارة |
| صلاحيات `module.object.action` | نفس الصيغة في GMES |
| أموال/كميات صحيحة (×1000، BigInt، تقريب نصف بعيد عن الصفر) | نفس المقياس للكميات |
| فحوص صحة لكل موديول (`health()`) | GMES: حفظ الكمية، سلسلة الـHash، تطابق المرايا، الـFeed بدون فجوات |
| نظام الوثائق (MAP مولّد، CHANGELOG، LESSONS، DECISIONS، CLAUDE.md) | GMES يتبنى نفس الهيكل |
| DataGrid، Shell، ⌘K، ثنائية اللغة | **مرحلة الواجهة:** نستخرجها كحزمة مشتركة بدل كتابة نسخة ثانية |
| **يبقى منفصلًا:** دفتر الأستاذ، التكلفة، المخزون المالي | التصنيع لا يحسب قيمة أبدًا |

## E7.2 من BAMS
| نأخذ | كيف |
|---|---|
| سجل Hash-chained موقّع + فحص السجلات | دفتر حركات التصنيع (مع توقيع Ed25519 اختياري لاحقًا) |
| "لا نمسح، لا نرجع التاريخ للخلف؛ الاستعادة = تغيير جديد" | نفس القاعدة |
| نسخ احتياطي متحقق + نسخة ثانية على قرص آخر + رفض الأقراص الشبكية للنسخ | نفس القواعد |
| "برنامج واحد لكل مجلد بيانات" (قفل) | نفس القفل |
| الأمان: قفل بعد محاولات، خمول، إجراءات لا تتم إلا من الجهاز نفسه | نفس السياسات |
| اقتران الأجهزة وشهادات مثبتة (pinned TLS) | لاقتران تطبيقات المنظومة ببعض (Eco Link) لاحقًا |
| المُثبّت الواحد (تثبيت + تحديث) وحماية الكود | نفس المنهج |
| **يبقى منفصلًا:** المزامنة متعددة الكتّاب ودمج العدادات | **ممنوعة لحركات الإنتاج** (ADR-015) |

## E7.3 من الثري دي
| نأخذ | كيف |
|---|---|
| نواة نقية حتمية (بلا `Date` ولا عشوائية داخل المنطق) | منطق الأوامر في GMES يستقبل الوقت والمعرفات من الخارج → اختبارات حتمية |
| "الحفظ للأبد" + ترحيلات للصيغ القديمة | لعقود eco: الإصدارات القديمة تفضل مقروءة |
| SSE للأحداث الحية | نفس الآلية لـ`/eco/v1/live` |
| نقاط الحفظ والحالة المولّدة (STATUS، checkpoints) | لإدارة المهام الطويلة |
| محاكي خط الإنتاج الحتمي (DES، فرع غير مدموج) | مستقبلًا لوحدة الجدولة APS: "لو غيّرت الترتيب يحصل إيه" |
| **يبقى منفصلًا:** الهندسة والمحرك المكاني | التصنيع يحفظ مراجع مكانية فقط، لا يحفظ أشكالًا |

## E7.4 من مشروع الأتمتة السابق
| نأخذ | كيف |
|---|---|
| فلسفة الشاشات، أكواد الشاشات، أنماط الاستعلام | نظام التصميم (وثيقة 06) |
| دروس الفشل الصامت (نتيجة فاضية بلا سبب، يوم خطأ، صفوف إجماليات، فلاتر موروثة) | قواعد الواجهة والتصدير |
| "القراءة آمنة، أي كتابة في نظام خارجي تحتاج موافقة صريحة" | **ينطبق على الموصلات:** `link-mizan` يكتب في ميزان فقط لأنواع مستندات محددة، بمستخدم محدود، وكل ما يكتبه يحمل مرجعه |
| **يبقى منفصلًا تمامًا:** كود الأتمتة، أسرار الدخول، بيانات أي عميل | لا يُستورد ولا يُنسخ للمنتج |

## E7.5 من HR-System (المُرحّل من Department-automation)
| نأخذ | كيف |
|---|---|
| قاموس بيانات الموارد البشرية للمصانع (14 مجالًا) والبيانات الصناعية بـ252 خطأ مزروع | مرجع عقود القوى العاملة القادمة (ورديات، مهارات، رواتب) واختباراتها |
| "لا يُستنتج الحذف من الغياب" و"الغياب صريح فقط" | نفس القاعدة في مرايا التصنيع: موظف غاب عن لقطة لا يُحذف |
| رفض ملف مكرر بالبصمة حتى لو تغير الاسم | نفس فكرة منع التكرار بالهوية |
| **يبقى منفصلًا:** المحرك وقاعدة `history.db` وواجهة الرفع | التصنيع لا يقرأها أبدًا؛ يستقبل العقود فقط |


## E7.6 واجهة واحدة للمنظومة (eco-ui) — 2026-09-28
- **مشترك:** التوكنز والمكونات وهيكل التطبيق (`packages/eco-ui/src`) — مصدرها هنا فقط؛ HR-System ينسخها بدون تعديل ببصمة SHA-256
  (نفس نمط `eco_schemas/`). كل منتج يغير **لونه المميز** فقط (`data-product`).
- **منفصل:** شاشات كل منتج وقواميسه وبياناته. المجموعة لا تعرف شيئًا عن التصنيع أو الأفراد (اختبار).
- **لاحقًا (اقتراح):** ميزان والثري دي يقدروا ياخدوا نفس المجموعة بنفس الطريقة لو المالك قرر توحيد الشكل — بدون تعديل مستودعاتهم من هنا.
