# E8) أساس البنية المشتركة للمنظومة — دراسة BAMS كمرجع معماري

تاريخ الدراسة: 2026-09-27. المرجع: `coolman1984/Mr.Ayman-HR` (BAMS) فرع `main` @`5f5b3ce`
(كل الفروع الأخرى مدموجة فيه). **قراءة فقط — لم يُعدَّل BAMS.** اختباراته السريعة (`test_unit` +
`test_convergence`، 33 اختبارًا) نجحت على نسخة مؤقتة. BAMS **ليس** نظام موارد بشرية ويبقى منتجًا مستقلًا.

> **الهدف:** مش إن كل البرامج تبقى نسخة واحدة، لكن إن كل واحد ميخترعش لوحده تسجيل الدخول والأجهزة
> والسجل والنسخ الاحتياطي والمزامنة. أساس مشترك (مواصفات + متجهات اختبار + تطبيقين مرجعيين Python/TS)،
> وكل برنامج يحتفظ بقواعد مجاله.

## E8.1 القاعدة الحرجة (قبل أي شيء)

**دمج BAMS متعدد الأجهزة لا يُطبَّق تلقائيًا على حركات التصنيع.** مناسب جدًا للبيانات الأساسية القابلة
للتعديل (اسم موظف، وصف محطة، إعداد)، ومرفوض لحقائق الإنتاج غير القابلة للرجوع أو الحساسة للكمية
(اكتمال، استهلاك، فاقد، سيريال، حركة مخزون) — إلا ببرهان رياضي أن البديل الأوفلاين يحفظ الهوية والترتيب
وحفظ الكمية.

**البرهان المختصر (مُختبر في `apps/mes-server/test/offline-merge-proof.test.ts`):**
1. **العداد (PN-counter):** الدمج = جمع كل الفروق. مسح نفس القطعة على جهازين أوفلاين يولّد فرقين
   مستقلين → المجموع يعدّ قطعة واحدة مرتين. الهوية ضاعت لأن الفرق لا يحمل هوية الشيء الفيزيائي.
2. **آخر كاتب يفوز (LWW):** حقيقتان متزامنتان على نفس الحقل (جيد على جهاز، فاقد على آخر) → واحدة تُمحى
   بصمت. حقائق الإنتاج لا "تُستبدل"، كلها حدثت.
3. **حفظ الكمية** (`مكتمل + فاقد ≤ مخطط`) قيد على **الحالة العالمية**. جهاز أوفلاين لا يرى ما سجله غيره،
   فكل جهاز يقبل حتى يمتلئ المخطط عنده → المجموع يتجاوز المخطط. لا يمكن ضمانه بدمج لاحق، فقط **بحجز مسبق**.
4. **البديل الآمن الوحيد المعروف:** *Escrow / Demarcation* — السيرفر يوزع حصصًا مسبقًا (كمية أو نطاقات سيريال)
   لكل محطة قبل انقطاعها؛ المحطة لا تتجاوز حصتها أوفلاين؛ الحقائق تُرسل كأوامر بـ`command_id` وتُتحقق.
   ده يحفظ الثلاثة. **مؤجل** (ADR-027) — حتى يُبنى ويُختبر، التصنيع = سيرفر مرجعي واحد.

BAMS نفسه يوثّق الحد ده: *"اتنين أجهزة ترجع نفس النسخة الاحتياطية في نفس الوقت → فرق الكمية يتطبق مرتين"*
(`DISTRIBUTED_SYNC_ARCHITECTURE.md` §13a). مقبول في مستلزمات استراحة، غير مقبول في مخزون مصنع.

## E8.3 خريطة الأنماط القابلة لإعادة الاستخدام

```
                          ┌────────────── Eco Foundation (مواصفات + متجهات اختبار) ─────────────┐
                          │ F1 Canonical JSON + Hash بمجال (domain-separated) + Ed25519         │
                          │ F2 Journal: changeset/ledger line، prev، sig، (origin,cseq)، verify │
                          │ F3 Identity: company id، device key، roster موقّع، clone detection  │
                          │ F4 Trust: TLS مثبت + جلسة موقعة + HMAC لكل طلب                      │
                          │ F5 Access: مفاتيح module.object.action + نطاق + profiles + audit    │
                          │ F6 Delivery بين التطبيقات: outbox/feed/inbox/acks (eco, ✅ في MES)  │
                          │ F7 Replication داخل التطبيق: BAMS fold (للبيانات القابلة للتعديل)   │
                          │ F8 Backup/Restore: online backup + integrity + قرص ثانٍ + تعويضي +  │
                          │    **اختبار استعادة آلي** (ينقص في كل الأنظمة)                       │
                          │ F9 Install/Update/Health: مُثبّت واحد، نسخة قبل الترقية، health      │
                          └───────────────▲──────────────────────────▲──────────────────────────┘
                                          │ Python (مرجع: BAMS)      │ TypeScript (مرجع: GMES/Mizan)
            ┌──────────────┬──────────────┴───┬──────────────┬───────┴──────┐
            │ HR-System    │ BAMS (مستقل)     │ GMES         │ Mizan         │ 3D
            │ F1-F9        │ F1-F9 كاملة      │ F1-F6,F8,F9  │ F5,F8,F9 الآن │ F1,F6 (لقطات)
            │ F7: بيانات   │                  │ F7: **ممنوع** │ F7: بيانات    │
            │ أساسية فقط   │                  │ لحقائق الإنتاج│ أساسية فقط    │
```

**مشكلتان مختلفتان، حلّان — لا حل ثالث (ADR-025):**
- **F7 النسخ داخل التطبيق الواحد** (نفس البرنامج على عدة PCs): نمط BAMS.
- **F6 التسليم بين تطبيقات مختلفة** (HR → MES، MES → ميزان): نمط eco (feed/inbox/acks).
- يتقابلان عند نقطة واحدة: **سجل التطبيق هو مصدر الـoutbox**. تغيير موظف في HR (أي جهاز) → سجل HR → لقطة eco.

## E8.4 BAMS مقابل ما بنيناه في GMES

| الموضوع | BAMS | GMES اليوم | الأقوى | القرار |
|---|---|---|---|---|
| **Outbox/Inbox** | لا يوجد بين تطبيقات؛ الـjournal نفسه هو ما يُتبادل (pull/push بـversion vectors) | `eco_outbox` في نفس المعاملة، feed بمؤشر، inbox بـ(source,id)، acks | مختلفان في المشكلة | يبقيان؛ BAMS لو تكامل مع المنظومة يكتب outbox من الـjournal |
| **ضمان التسليم** | مرة واحدة فعليًا: `cseq == have+1` لكل مصدر، التكرار يُتجاهل، الفجوات تنتظر | مرة واحدة فعليًا: مؤشر + dedupe + مستند يحمل مرجع الحدث | متعادل | نفس المبدأ؛ مصطلحات موحدة في E3 |
| **الدفتر الموقّع** | سلسلة لكل origin + **توقيع Ed25519 لكل changeset** + فحص fork | سلسلة واحدة SHA-256 بلا توقيع + triggers + مرساة يومية (مخططة) | **BAMS** | ADR-026: صيغة سجل موحدة (Hash بمجال + canonical + توقيع جهاز). HR ينفذ السلسلة الآن والتوقيع مع هوية الجهاز (F2)؛ دفتر MES v2 يتبناها بترحيل |
| **Canonical JSON** | مفاتيح مرتبة، بلا مسافات، UTF-8 | `stable()` مفاتيح مرتبة بلا مسافات | متعادل لكن **غير مثبت أنه متطابق** | متجهات اختبار مشتركة Python↔TS (مُنفَّذة: `eco-contracts` و`HR-System`) |
| **المستخدمون** | نظام كامل: PBKDF2 600k، قفل، خمول، profiles، روابط، إجبار تغيير كلمة السر | مفاتيح API بنطاقات فقط، بلا مستخدمين | **BAMS / ميزان** | MES يتبنى نموذج ميزان (TS) بنفس صيغة المفاتيح؛ HR يتبنى نموذج BAMS (Python) |
| **الأجهزة** | هوية + roster موقّع + TLS مثبت + clone detection | مفتاح API لكل جهاز | **BAMS** | F3/F4 حزمة؛ MES يضيف roster قبل تعدد المحطات في الإنتاج |
| **النسخ الاحتياطي** | متحقق + قرص ثانٍ + journal خارج الاستعادة + استعادة تعويضية | **لا يوجد** (مصمم فقط) | **BAMS** | F8؛ + اختبار استعادة آلي (جديد للجميع) |
| **التشغيل أوفلاين** | كل جهاز يكمل | السيرفر مرجعي؛ الروابط بين التطبيقات تتحمل الانقطاع ✅ | لكلٍ مجاله | E8.1 |
| **التعافي** | إعادة بناء الجداول من السجل (مختبر بنفس البصمة)، epochs | الـprojections مفحوصة ضد الدفتر في health؛ **لا أداة إعادة بناء بعد** | **BAMS** | MES: `rebuild-projections` من الدفتر (مرحلة F3) |

## E8.6 الأساس المشترك الموصى به
1. **مواصفات مكتوبة + متجهات اختبار** لكل نمط (F1…F9)، وليس خدمة مركزية ولا قاعدة مشتركة.
2. **تطبيقان مرجعيان**: Python (يُستخرج من HR-System الذي يعيد تنفيذ تصميم BAMS) وTypeScript (`packages/eco-*` في GMES).
   كل تطبيق مرجعي يمر على **نفس المتجهات**؛ أي اختلاف = اختبار أحمر.
3. **لا نسخ ميكانيكي لكود BAMS**: BAMS يبقى المرجع، والكود الجديد يعيد التصميم بعقود واضحة. (استثناء ممكن
   لاحقًا بقرار: `ed25519.py` الخالص لو Python القديم على جهاز العميل مفيهوش `cryptography`.)
4. **كل تطبيق يختار ما يناسب مجاله** من الطبقات، وF7 ممنوعة على حقائق الإنتاج.
