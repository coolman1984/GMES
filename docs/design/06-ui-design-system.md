# 6) نظام التصميم البصري — قريب من فلسفة الأنظمة المؤسسية

> **الحالة (2026-09-28، مرحلة UX):** التوكنز صارت كودًا حيًا في ملف واحد: `packages/eco-ui/src/tokens.css`
> (فاتح/داكن، كثافة، لون كل منتج)، والمكونات في `packages/eco-ui/src/eco-ui.{css,js}` (ADR-029). القيم اللونية
> ما زالت **مؤقتة** لحد ما توصل صور المرجع: نستخرج منها الألوان والمسافات وأحجام الخطوط (§6.6)
> ونعدل `tokens.css` وحده — وكل الشاشات في GMES وHR-System تتغير تلقائيًا. قائمة القبول البصري: `docs/ux/visual-acceptance.md`.
> جدول §6.4: الجدول والرسوم بُنيت داخل `eco-ui` بدل AG Grid/ECharts (ADR-029).

## 6.1 تنبيه قانوني/تجاري أولًا
"قريب جدًا في الفلسفة" ✅ — "نسخة من نظام تجاري آخر" ❌.
- **ناخد:** طريقة التشغيل، الكثافة، ترتيب الشاشة، نمط الشروط-استعلام-جدول، أكواد الشاشات، MDI.
- **منخدش:** شعار أو اسم أي نظام تجاري آخر، الأيقونات أو الصور بتاعتهم، أو أي ملف/كود من النظام.
- المنتج له **اسم وشعار ولون مميز خاص بيه** (Accent color). ده مش بس حماية قانونية —
  ده اللي بيخلي العميل يفتكر اسم منتجنا: **Itqan · إتقان**.

## 6.2 فلسفة الشاشة (المبادئ)
1. **كثافة معلومات عالية للمكتب:** صف جدول 24–26px، خط 12–13px، مفيش مساحات فاضية
   "تسويقية". المستخدم الخبير عايز يشوف 40 صف مرة واحدة.
2. **نمط واحد يتعلم مرة واحدة:** كل شاشة استعلام = شروط فوق → استعلام → جدول → تفاصيل.
3. **الكيبورد أولًا:** F5 استعلام، Enter ينقل للخانة التالية، Ctrl+E تصدير، Ctrl+K بحث
   الشاشات، الأسهم في الجدول.
4. **الحالة دايمًا صريحة:** جاري التحميل / N صف في وقت كذا / خطأ + السبب. **مفيش جدول
   فاضي من غير جملة بتقول ليه** (درس gotcha #12 و#14).
5. **الفلاتر الإلزامية عليها نجمة ولون**، والاستعلام ميتنفذش من غيرها — بدل ما يرجع صفر.
6. **وضع المحطة عكس المكتب تمامًا:** أزرار ≥ 64px، خط ≥ 20px، ألوان حالة قوية، صوت.
7. **العربي RTL كامل** (الجدول، الشجرة، الأسهم، Gantt)، والأرقام والأكواد تفضل LTR جوه السطر.

## 6.4 المكونات (Component inventory)
| المكون | ملاحظات |
|---|---|
| App shell | شريط علوي + قائمة شجرية قابلة للطي + تابات MDI (حد أقصى قابل للضبط، تحذير عند التجاوز) + breadcrumb بالكود |
| Screen search | بحث بالكود أو الاسم (عربي/إنجليزي)، Ctrl+K |
| Condition panel | شبكة حقول 4–6 أعمدة، قابلة للطي، إلزامي بنجمة، حفظ "فلاتري المفضلة" |
| Org/Line picker | شجرة مصنع/منطقة/خط/محطة مع اختيار متعدد (زي شجرة المنظمة في الأنظمة الكبيرة) |
| Date-range | يوم إنتاج (مش تاريخ ساعة) + اختصارات: اليوم، أمس، الوردية الحالية، هذا الأسبوع |
| Data grid | AG Grid بثيم خاص بنا: أعمدة ثابتة، إخفاء/ترتيب أعمدة محفوظ لكل مستخدم، صف إجماليات، تلوين الحالة، نسخ خلايا |
| Result bar | الفلاتر المطبقة + عدد الصفوف + وقت الاستعلام + تصدير |
| Master-detail | جدول فوق، تفاصيل/تابات تحت، مقسم قابل للسحب |
| Form dialog | تحقق فوري، رسائل عربية واضحة |
| E-signature dialog | كلمة السر + السبب (قائمة + نص) |
| Status chip | بألوان `--st-*` + أيقونة (عشان عمى الألوان) |
| Station widgets | حقل مسح ضخم، أزرار حالة كبيرة، شريط تقدم الأمر، بانر الاتصال |
| Board widgets | KPI كبير، مخطط/فعلي بالساعة، مؤشر حالة الخط، شريط آخر التوقفات |
| Charts | ECharts بثيم موحد: Pareto، OEE waterfall، SPC، Gantt |

## 6.5 قواعد الكتابة في الواجهة
- رسائل الخطأ = **إيه اللي حصل + تعمل إيه**: "القطعة SN-451 محجوزة من الجودة (سبب: مقاس). كلّم مشرف الجودة." مش "Error 409".
- المصطلحات موحدة في قاموس واحد (أمر عمل، وحدة، لوت، فاقد، إعادة تشغيل، حجز، إفراج…).

## 6.6 لما توصل صور المرجع — هنعمل إيه بالظبط
**محتاجين (مع إخفاء أي بيانات إنتاج أو أسماء أو أرقام طلبيات):**
1. الشاشة الرئيسية بعد الدخول (الشريط العلوي + القائمة).
2. شاشة استعلام فيها نتيجة (زي Production Plan by Order).
3. نافذة منبثقة/حوار (Popup).
4. شجرة الـOrg/Division مفتوحة.
5. أي شاشة Master-Detail.
6. لو متاح: شاشة إدخال/حفظ، وشاشة فيها رسم بياني.

**التحليل:** استخراج لوحة الألوان بالقيم (من البكسلات)، أحجام الخط والصفوف والحواف،
شبكة المسافات، أنماط الأزرار والأيقونات، ترتيب العناصر — ثم تحديث التوكنز §6.3
وعمل **صفحة Style Guide حية** بكل المكونات، ومقارنة جنب-لجنب مع الصور قبل ما نبني أي شاشة.
